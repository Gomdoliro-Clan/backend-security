# 애플리케이션 보안 검토 과제

ProcureFlow의 소스와 로컬 실행 환경을 검토해 의도적으로 숨겨진 **애플리케이션 취약점 5개**를 찾고 수정하세요. 실제 등록 CVE를 찾는 공급망 과제가 아닙니다. 각 결함을 CVE처럼 재현하고 CWE·CVSS·영향 범위·수정안을 포함한 보안 보고서로 작성하는 과제입니다.

| 목표 등급 | 개수 | 권장 점수 |
|---|---:|---:|
| Low | 2 | 각 10점 |
| Medium | 1 | 15점 |
| High | 1 | 25점 |
| Critical | 1 | 30점 |
| 수정 후 정상 업무 품질 | — | 10점 |

심각도가 높을수록 입력 지점과 실제 위험 동작이 더 멀리 떨어져 있습니다. 단순 문자열 검색만으로는 전체 영향을 설명하기 어렵고, 인증 주체·조직 경계·저장 데이터·비동기 작업을 함께 추적해야 할 수 있습니다.

## 진행 조건

- 권장 대상: Spring MVC/JDBC와 PostgreSQL을 경험한 중급 이상 학습자
- 권장 시간: 개인 8~12시간 또는 2인 팀 1~2일
- localhost의 본인 실습 인스턴스와 합성 데이터만 사용
- Controller → Service → Repository뿐 아니라 내보내기, 저장 후 재사용, 예약 작업도 검토
- 스캐너 결과는 단서로 사용할 수 있지만, 이 과제의 목표는 의존성 CVE가 아니라 코드의 신뢰 경계입니다.

## 안전한 검증 규칙

- 명령 실행, 외부 URL/DNS 접속, 역방향 셸, 외부 데이터 전송을 시도하지 않습니다.
- 대량 요청, 메모리·CPU·디스크 고갈, 동시성 부하 시험을 수행하지 않습니다.
- DB 변경이 필요한 경우 제공된 합성 데이터와 본인이 생성한 레코드만 사용합니다.
- 코드 실행 가능성은 계산식, 런타임 버전 조회처럼 부작용 없는 표현으로만 증명합니다.
- SQL 관련 항목은 정적 호출 경로 또는 mock 기반 단위 테스트를 우선하며, DB 파괴·권한 상승 쿼리를 실행하지 않습니다.
- Compose는 포트를 loopback에만 공개하고 컨테이너 네트워크의 외부 통신을 차단합니다. 외부에 배포하지 마세요.

## 제출물

각 취약점마다 다음을 작성합니다.

1. 자체 식별자(`PFV-2026-xxx` 형식), 제목, CWE
2. CVSS 3.1 점수·벡터와 등급 판단 근거
3. 입력 → 검증/저장 → 위험 동작까지의 파일·메서드 단위 호출 경로
4. 필요한 역할, 조직, 사용자 상호작용, 비동기 처리 등 공격 전제
5. 파괴적 동작 없는 최소 재현과 기대 보안 동작
6. 방어적 코드 수정 diff와 정상 기능 회귀 테스트

추가 결함을 발견했다면 목표 5개와 분리해 부록에 기록하세요. 등록 라이브러리 CVE, 실습용 기본 비밀번호, 로컬 DB 접속 정보는 이 과제의 5개 목표에 포함하지 않습니다.

## 완료 기준

- `./mvnw verify` 통과
- 로그인, 역할별 접근, 구매 승인, 청구 정산, 보고서, 공개 견적 흐름 정상 동작
- 조직 경계와 출력·쿼리·템플릿 처리에 적절한 방어가 적용됨
- 수정한 호출 경로마다 회귀 테스트가 존재함
